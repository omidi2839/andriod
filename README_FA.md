# Almas Shop — نسخه اولیه سورس 1.0.0
اپ Flutter مستقل مشتریان، عربی و RTL، بدون WebView. پروژه کارکنان Almas Catalog Native را جایگزین نمی‌کند.

## پیش‌نیازهای سرور
- نسخه 0.4.9.91 مرکز عملکرد بازاریابی: فقط آداپتور موتور اجتماعی موجود اضافه شده است.
- نسخه 0.8.39 ویترین عمومی: API اختصاصی اپ اضافه شده است؛ رفتار سایت عمومی حفظ شده است.
- PHP و Perfex همانند نسخه‌های پایه، با CSRF و نشست فعال، کوکی معتبر، HTTPS واقعی، دامنه و مسیر API که ریدایرکت HTTP ندارد. آدرس پیش‌فرض سورس https://sejadalmas.iq/ است؛ دسترسی آن در این محیط تأیید نشده. اگر reverse proxy دارید، HTTPS باید در origin به صورت معتبر شناخته شود؛ هدر ارسالی از کلاینت قابل اعتماد نیست. غیرفعال کردن TLS/CSRF راه‌حل نیست.
- فروشنده پیش‌فرض آنلاین، نوع فروش آنلاین، مجازبودن محصولات و تنظیمات موتور مرکزی از نسخه‌های قبل برقرار باشد.
- حساب مشتری از مخاطب اصلی فعال Perfex متعلق به مشتری فعال و شماره یکتای ثبت‌شده استفاده می‌کند؛ رمز همان رمز هش‌شده مخاطب است. برای مشتری فاقد حساب/رمز، مدیر باید ابتدا در Perfex مخاطب اصلی با شماره یکتا و رمز امن ایجاد/بازیابی کند؛ شماره تلفن به تنهایی رمز نیست. اگر شماره در قالبی ثبت شده که ۷ رقم پایانی پیوسته نیست، ممکن است نیاز به اصلاح شماره در CRM باشد. بازیابی رمز و ثبت‌نام خودکار در اپ فعلاً فراهم نیست.

## ساخت روی ویندوز
Flutter SDK، Android Studio و ابزارهای SDK را نصب کنید و flutter doctor اجرا کنید. پوشه ZIP را استخراج کنید. در PowerShell:
```
.\bootstrap.ps1
flutter run --dart-define=ALMAS_API_BASE=https://sejadalmas.iq/
flutter build apk --release --dart-define=ALMAS_API_BASE=https://sejadalmas.iq/
```
برای macOS/Linux: `./bootstrap.sh`. برای iOS به macOS/Xcode و signing نیاز است. اسکریپت bootstrap فایل‌های platform را با Flutter SDK می‌سازد؛ سورس ZIP شامل runner آماده یا APK نیست. قبل از انتشار release باید امضای تولید و شناسه اپلیکیشن را تنظیم کنید. نام بسته پیشنهادی iq.sejadalmas.almas_shop است.

## امکانات پیاده‌شده در سورس
- مرور آزاد کاتالوگ واقعی و نمایش تصاویر، اندازه، رنگ، قیمت آنلاین، تخفیف پایه و موجودی. بارگیری ۱۲تایی و sliver grid؛ فهرست و فیلتر از manifest موجود.
- کارت‌ها، جزئیات، علاقه‌مندی، سبد خرید، ورود به هنگام ثبت سفارش، تأیید مجدد قیمت/موجودی سمت سرور، ارسال درخواست به صندوقدار (نه پرداخت یا فاکتور قطعی)، مشاهده وضعیت درخواست‌های مشتری خود.
- گفتگوی متنی و کارت‌های محصول از همان `social_ai_generate` مشترک کانال‌ها؛ نشست جداگانه سمت سرور؛ برای حریم خصوصی هیچ شماره تلفن یا رمز را در چت وارد نکنید. ارجاع واقعی به کارشناس، آپلود عکس/صوت و AR بومی در این نسخه نیست. لینک صفحه محصول/فضای من در مرورگر بیرونی باز می‌شود. موتور وب فعلی تغییر نکرده است و یکسان‌سازی کامل آن با موتور کانال‌ها کار مستقل است.
- سبد و علاقه‌مندی در حافظه اجرای اپ است؛ با بستن کامل اپ باقی نمی‌ماند. نشست مشتری در CookieJar حافظه‌ای است و رمز ذخیره نمی‌شود.
- درخواست سفارش به مسیر mobile_checkout محدود به نشست مشتری و nonce است. مسیر عمومی قبلی برای سایت همچنان برقرار است؛ ورود اجباری فقط روی مسیر اپ اعمال می‌شود. درخواست ارسال‌شده به معنای رزرو یا پرداخت نیست. کلید درخواست در همان نشست از تکرار جلوگیری می‌کند؛ پس از قطع ارتباط طولانی/بستن اپ، قبل از ثبت مجدد وضعیت سفارش‌ها بررسی شود.

## آزمون‌های لازم روی محیط آزمایشی
1. مهمان کاتالوگ و جست‌وجو؛ عدم نمایش کالای پنهان، موجودی ناموجود یا اطلاعات داخلی.
2. ورود با شماره ثبت‌شده و رمز صحیح، رمز غلط، شماره تکراری، شماره بدون مخاطب فعال. عدم ورود یا ثبت سفارش روی HTTP.
3. سبد خرید مهمان، ورود و بازگشت به همان سبد. تأیید سفارش، تغییر قیمت و موجودی و رد سفارش بدون نشست. بررسی سفارش مشتری دیگر و تکرار ارسال.
4. فروشنده هوشمند با متن «اريد سجاده ٤*٣»؛ مقایسه پاسخ با واتساپ و محیط آزمایش؛ کلیک کارت پیشنهادی و افزودن به سبد.
5. تأیید داده واقعی، عدم خطای 419 در HTTPS، بررسی کارایی، ظاهر موبایل و امنیت؛ پرداخت اینترنتی/اقساطی بومی و AR بومی نیازمند توسعه جداگانه.

## وضعیت اعتبارسنجی
PHP lint و ZIP integrity بررسی شده‌اند. Flutter/Dart SDK و اتصال به سرور واقعی در محیط ساخت در دسترس نبودند؛ `flutter analyze` و build اجرا نشده‌اند. این سورس پیش‌نمایش توسعه است و نه نسخه آماده انتشار فروشگاه اپ.
