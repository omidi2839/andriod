# ویترین همراه الماس — Android Native 1.0.4 (پروژه سورس)

مبنای قرارداد ارتباطی: almas_catalog 0.1.10، و اپ قبلی Flutter 1.0.3 در شاخه feat/almas-catalog-native-1.0.0. رابط جدید بومی Flutter است، نه WebView. شناسه پیش‌بینی‌شده مطابق دستور ساخت قبلی: iq.sejadalmas.almas_catalog_native. آدرس پیش‌فرض https://sejadalmas.iq/almas_catalog/catalog (قابل تغییر هنگام ورود).

چهار تب: محصولات با چهار قیمت کانال، تخفیف، فیلتر و صفحه‌بندی cursor؛ رگال‌ها با طبقه، ردیف، جستجو و سایر اندازه‌های هم‌کد و هم‌رنگ؛ موجودی واقعی/رزرو/قابل فروش؛ رزروها با جزئیات شماره فاکتور، تاریخ و تعداد. اطلاعات از سرور می‌آید و اپ موتور مستقل قیمت‌گذاری یا تغییر موجودی ندارد. رابط فارسی/عربی، بدون تصاویر و بدون ذخیره دائمی اطلاعات حساس. ورود با HTTPS و کوکی نشست در حافظه، بدون دور زدن گواهی و بدون تغییر API سرور. عدم تأیید موجودی با خط تیره نمایش داده می‌شود، نه صفر. جستجوی کالا با ارسال کادر جستجو یا دکمه تازه‌سازی انجام می‌شود.

## پیش‌نیاز سرور
ماژول almas_catalog 0.1.10 و وابستگی‌های درج‌شده در README آن؛ ویترین فعال و HTTPS معتبر. همان حساب مشترک ویترین همراه. نصب APK مستقل از نصب ماژول است.

## ساخت APK آزمایشی در ویندوز
Flutter 3.32.8، JDK 17، Android SDK و دسترسی شبکه برای دریافت وابستگی‌ها نیاز است. در PowerShell در پوشه پروژه اجرا کنید:

```powershell
powershell -ExecutionPolicy Bypass -File .\build-android.ps1
```

در Linux/macOS: `bash build-android.sh` (به Python 3 نیز نیاز دارد).
خروجی: `dist/AlmasCatalogNative-1.0.4-test.apk`؛ فقط اگر مراحل Flutter analyze/test/build موفق باشند. میزبان Android به‌وسیله Flutter create ساخته می‌شود. ساخت آزمایشی با تنظیم امضای پیش‌فرض Flutter انجام می‌شود و برای جایگزینی مستقیم APK قبلی باید کلید امضای همان APK استفاده شود. ابتدا اطلاعات ضروری را حفظ کنید؛ اگر امضا متفاوت بود، اندروید اجازه نصب روی نسخه قبلی را نمی‌دهد. برای انتشار سازمانی، کلید سازمانی ثابت تنظیم شود؛ هیچ کلید یا رمز در بسته نیست.

## وضعیت تحویل
این بسته سورس است، نه فایل APK. در محیط تهیه Flutter/Dart/Android SDK نصب نبود و دسترسی به مخزن دانلود SDK برقرار نشد؛ بنابراین کامپایل، flutter test و نصب روی گوشی انجام نشده است. آزمون‌های Dart در پروژه برای اجرای زمان ساخت قرار گرفته‌اند. API با بررسی فایل‌های PHP/JS نسخه 0.1.10 تطبیق داده شده، اما تست عملی سرور، ورود و عملکرد چهار تب باقی مانده است. فونت پیش‌فرض دستگاه به‌جای فونت خارجی استفاده می‌شود.

## ساخت با GitHub Actions
در صورت قرار دادن محتوای این ZIP در ریشه یک مخزن اختصاصی اپ، workflow موجود در `.github/workflows/build-apk.yml` از تب Actions به‌صورت دستی اجرا می‌شود و پس از موفقیت فایل APK را در Artifacts قرار می‌دهد. این workflow در محیط فعلی اجرا نشده و مخزن موجود کاربر تغییر نکرده است.
